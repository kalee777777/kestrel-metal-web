阶段 3

谷歌发现内容(三条入口)

可加速,不能跳过
🤖 自动入口① sitemap 抓取Googlebot 周期性读 sitemap.xml 发现新 URL(慢,数天~数周)
👤 人工(强烈建议)入口② GSC 请求索引Search Console → 网址检查 → "请求编入索引",当天触发抓取你的操作 · 每篇 1 分钟
🤖+👤 AI 辅助入口③ 内链引导博客索引卡片/文章互链/产品页入口(回收脚本自动补,审核靠人)

谷歌内部处理(全自动,你只能影响输入质量)

典型耗时:抓取后 1~7 天
🤖 自动① Googlebot 抓取读 HTML 源码(不执行 JS)→ 无 JS 可读是硬门槛
→
🤖 自动② 渲染与解析canonical 判定 → 重复/规范 URL 归一

🤖 自动③ 索引评估质量评分:内容唯一性/结构化数据/内链权重你能影响的:内容质量+schema+内链
→
🤖 自动④ 收录进入索引,site: 查询可见,GSC 覆盖报告出现

阶段 5

效果监控与迭代(月度循环)

≈2 小时/月
👤 人工GSC 数据查看收录覆盖/排名/点击 → 发现未收录页补推
👤 人工GA4 流量 + ai_referralAI 引用带来的会话监控
👤 人工基线 Prompt 测试ChatGPT/Perplexity 测 10 条 → Admin 基线验证记录引用率
🤖+👤 AI 辅助低分页补内容Admin 评分排序 → AI 补定义句/数据点 → 人审核
人工必须做的 4 件事:① GSC 请求索引(每篇新文章,加速收录的关键一步);② GA4/GSC 月度查看;③ 基线 Prompt 测试;④ 发布新内容后知会 AI 跑回收脚本。
全自动的部分:内容生产、A 轨直传、Gitee 部署、Google 抓取→收录→排名全过程。
当前最大缺口(A 轨):工作流直传不进仓库/不挂索引/缺 og —— 每次发布后需 B 轨回收补救;建议后续改造工作流把"git 提交 + 博客索引"纳入自动步骤。
