## 二、诊断过程与结论

### 2.1 根因判定

**直接诱因**：Google 2026 年 9 月 spam update（09-24 开始，约两周，全球所有语言，**不针对链接垃圾、专打内容型垃圾**）。受影响站长的典型损失 ~95%，与本站跌幅完全一致，时间精确重合。

**为什么被波及——自身风险画像**（按权重）：

1. **规模与资历倒挂**：6 个半月新域名上挂着 90+ 篇文章，大部分由 DeepSeek 每日自动生成发布 = "规模化内容"字面画像
2. **同主题关键词变体多篇并存**：chain link 指南 4 篇、gabion supplier 4 篇、galvanized wire 2 篇、"Top 10"竞品榜单 3 篇（含 1 篇 KV 独有）
3. **选题机制为"竞品缺口驱动"**（133 个缺口词 → 自动成文）= 字面命中 Google 对"为搜索引擎而非用户生产内容"的定义
4. **站外权威为零**：无外链、made-in-china/Alibaba 双站搜索 0 结果、Perplexity 引用 0/10

**定性**：算法性压制（indexed but not served）——页面留在索引中，Google 大幅提高展示门槛。比整站除名轻一级，恢复依赖后续刷新，而非即时。

### 2.2 已排除的可能（全部实证核查）

| 检查项 | 方法 | 结果 |
|--------|------|------|

## 四、经验教训（含本次操作中的失误）

1. **零外部权威的站，内容规模是负债不是资产**。这次被压制的主因不是"做错了什么"，而是"新域名 + 规模化 AI 内容"的画像本身。恢复后发文必须换模型：每周 1-2 篇、人工审核、选题改为"竞品缺口 ∩ 有真实素材可写"双重过滤。
2. **KV-only 内容是扫描盲区**。批次 4 的竞品榜单之所以漏网，是因为所有审计脚本只扫 git 仓库。以后内容审计必须包含 `/api/blog?limit=100` 拉取线上全量。
3. **批量脚本改文件前必须先写好验证，提交前必须核对 git diff**。本次曾因一个列表过滤 bug 误删 blog-news.html 51 行无辜内容（导航 + 47 张卡片），靠"应删 4 张却报 0 张"的异常发现并从 git 恢复。教训已固化为流程：先 diff 后 commit。
4. **`_redirects` 目标路径必须带前导斜杠**，本次曾漏写（自查发现，未上线）。现有 396+ 条规则可作对照模板。
5. **cron 触发器在 Git 集成部署下不可增删**（实测），人工闸门一律用 KV 开关 + 代码检查实现。
6. **GSC 各报告的数据滞后要计入判断**：效果报告 1-2 天且每日快照不回填；网页索引报告约一周（09-30 查到的还是 09-21 快照）。勿用滞后数据下当日结论。
7. **"site: 查询"在国内网络出口下不可靠**（Bing 亦然），收录判断以 GSC 报告为准。
8. 算法性打击的恢复**要等下一轮刷新**，应急处置的目标是"窗口来了接得住"，不是立即恢复。
